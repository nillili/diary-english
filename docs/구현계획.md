# 일기 영어회화 데스크톱 앱 상세 구현 계획

작성일: 2026-09-24
상태: 구현 전 계획. 라이브러리 설치, 모델 실행, 음질·재생 테스트는 아직 수행하지 않았다.
요구사항 원문: [의도코드.md](./의도코드.md)

## 0. 이 문서를 사용하는 방법

이 문서는 다른 구현 AI가 순서대로 실행할 수 있도록 작업 단위, 파일 책임, 데이터 계약, 실패 처리와 완료 조건을 지정한다. 파일 이름과 내부 구조는 이 계획에서 제안하는 구현 기준이다.

1. 아래 확정 요구사항과 미확정 항목을 먼저 읽는다.
2. 단계 0부터 순서대로 진행한다. 선행 단계의 완료 기준을 통과하지 못했으면 의존하는 작업을 완료 처리하지 않는다.
3. 구현한 단계마다 `docs/구현진행.md`에 변경 파일, 실행한 검증, 결과, 남은 제한을 기록한다.
4. 테스트 도구로 검증한 결과와 사람이 실제로 듣고 확인한 결과를 구분한다.
5. 모델이 없는 환경에서는 대체 구현으로 UI·저장소를 개발할 수 있으나, 실제 번역·음성 기능이 완성됐다고 보고하지 않는다.
6. 사용자 최신 지시가 우선한다. 기존 의도 문서의 초기 edge-tts 추천과 온라인 생성 화면은 예전 후보안이다. 본 계획은 사용자가 기존에 사용하는 **MeloTTS + soundfile 재사용**을 우선 검증한다.
7. 이번 요청의 끝부분인 “라이브러리는”은 미완성 문장이다. 추가 지정은 아직 확인되지 않았다. 사용자가 추가로 지정하면 아래 추천 구성과 충돌하는 부분만 수정한다.

## 1. 변경하면 안 되는 요구사항

| ID | 요구사항 | 완료 증거 |
| --- | --- | --- |
| R01 | Python 데스크톱 앱 | 브라우저 없이 앱 창 실행 |
| R02 | 일기 입력창과 읽기 전용 번역창 | 오늘의 학습 탭의 두 텍스트 영역 |
| R03 | 입력창 바로 아래 변환 버튼 | 타이핑만으로 번역 요청이 발생하지 않음 |
| R04 | 한국어 일기를 미국식 영어로 변환, 스타일 선택 | 스타일 값이 번역 요청에 전달되고 결과를 검수 |
| R05 | 기본 스타일은 중년층 일상회화 | 첫 실행 기본 설정과 번역 검수 |
| R06 | 재생/일시정지 버튼과 별도 정지 버튼 | 재생 상태별 동작 검증 |
| R07 | 한 문장씩 재생, R 반복, Space 다음 문장 | 종료 후 대기 및 단축키 검증 |
| R08 | 오늘의 학습 하단은 저장 버튼 하나 | 내보내기·폴더 열기 버튼 없음 |
| R09 | 보관함 목록 한 번 클릭 → 첫 탭으로 이동 | 별도 학습 열기·내보내기 버튼 없음 |
| R10 | MP3 보관과 나중의 반복 학습이 핵심 | 앱 재시작 및 네트워크 차단 후 저장 자료 재생 |
| R11 | 남성/여성 음성 선택 | 실제 지원 음성으로 생성·청취 확인. 아래 미해결 조건 참조 |
| R12 | 유료 API 없이 구현 가능한 구성 우선 | 로컬 모델·무료 도구 조합과 비용 설명 |

보관함의 `[저장 폴더 열기]`는 사용자가 제거한 세 버튼에 포함되지 않았고 현재 의도 문서에 남아 있으므로 유지한다. 클릭 시 선택 자료의 폴더를 OS 파일 관리자로 연다. 선택 자료가 없으면 비활성화한다.

초기 범위에 넣지 않을 것: 마이크 입력, 음성 인식, 발음 점수, 로그인, 클라우드 동기화, 웹·모바일 버전, 배경 음악, 자동 다음 문장 재생, 자동 영구 저장, 사용자 목소리 복제.

## 2. 미확정 항목과 진행 가능한 범위

| 항목 | 현재 판단 | 구현 지침 |
| --- | --- | --- |
| 대상 OS | 아직 사용자 미지정 | 현재 개발 OS를 기록하고 개발 가능. 설치 프로그램을 다른 OS에서 검증했다고 주장하지 않음 |
| 기존 MeloTTS 환경 | 기존 사용 중이라는 사실만 확인 | 기존 프로젝트 경로·Python 및 패키지 버전을 확인해 별도 환경에서 재현. 기존 환경을 덮어쓰지 않음 |
| 번역 모델 | Ollama의 로컬 Qwen 계열을 후보로 제안 | RAM/GPU와 한국어→영어 품질 확인 후 정확한 모델 ID·해시 기록 |
| 미국 영어 남녀 음성 | MeloTTS 문서의 영어 화자는 억양별 구분 | 이름이나 음높이로 성별을 추정하지 않음. 실제 지원 확인 전 R11은 미완료 |
| 추가 라이브러리 지정 | 사용자 문장 미완성 | 당장은 아래 추천안을 사용한 계획으로 작성. 추가 답변을 우선 반영 |

남녀 음성을 MeloTTS만으로 충족하지 못하면: 해당 사실과 추가 엔진 후보를 보고하고 선택을 받는다. 그동안 저장·재생·보관함은 개발한다. 미지원 선택을 동작하는 것처럼 표시하거나 사용자가 고른 성별을 무시해 다른 음성을 만들지 않는다. 이 조건이 해결되지 않았다면 전체 요구사항 완료로 표시하지 않는다.

## 3. 추천 기술 구성과 버전 정책

| 구분 | 추천 | 책임 |
| --- | --- | --- |
| GUI | PySide6 Widgets | 탭, 텍스트박스, 표, 버튼, 파일 선택 |
| 재생 | PySide6 QtMultimedia의 QMediaPlayer + QAudioOutput | 문장 MP3의 재생·일시정지·정지 |
| 번역 | 로컬 Ollama + 검증된 공개 모델 | 미국식 회화 스타일 적용 번역 |
| HTTP | Python 표준 urllib.request | 로컬 Ollama 호출. 요청은 작업 스레드에서 수행 |
| 음성 생성 | MeloTTS | 영어 문장 → PCM 음성 배열 |
| 오디오 파일 | soundfile + numpy | 문장별 MP3 쓰기, PCM 합치기, 전체 MP3 쓰기 |
| 데이터 | dataclasses, json, pathlib, uuid, datetime | 계약·메타데이터·경로 처리 |
| 백그라운드 | QObject 작업자 + QThread | 번역·TTS·파일 작업을 화면과 분리 |
| 검증 | pytest, pytest-qt | 저장·상태 전환 및 GUI 이벤트 테스트 |

Python 버전을 지금 임의로 고정하지 않는다. 먼저 기존 MeloTTS의 정상 동작 버전을 확인한다. 새로 탐색할 경우 Python 3.10/3.11을 후보로 시도하되 설치·실행 통과 결과로 결정한다. 모든 패키지를 최신 버전으로 일괄 업그레이드하지 않는다.

MeloTTS 저장소는 일부 오래된 의존성 버전을 고정하고 있다. SoundFile도 버전에 따라 지원 Python이 다르므로 **동시에 동작하는 조합을 검증하고 고정**해야 한다. [MeloTTS 의존성](https://github.com/myshell-ai/MeloTTS/blob/main/requirements.txt), [SoundFile 변경 기록](https://github.com/bastibe/python-soundfile#news)

버전 고정 산출물:

- `requirements.in`: 앱 직접 의존성과 선택 근거.
- `requirements.lock.txt`: 검증한 환경의 정확한 패키지 버전. CPU/GPU·OS 조합이 다르면 별도 lock 파일.
- MeloTTS는 검증한 Git commit SHA로 고정. 이동하는 main 브랜치만 의존성에 쓰지 않는다.
- `docs/환경검증.md`: OS, Python, Qt, torch/torchaudio, numpy, soundfile, libsndfile 버전, MeloTTS SHA, 모델 ID, 장치(cpu/cuda 등), 테스트 결과.
- 기존 환경과 GUI가 한 환경에 공존할 수 없으면 별도 TTS 프로세스 방식의 추가 설계를 먼저 기록한다. 무작정 GUI 안에서 의존성을 변경하지 않는다.

공식 기능 근거:

- MeloTTS의 `EN` 모델과 `EN-US` 화자는 공식 Python 예제에 있다. [사용법](https://github.com/myshell-ai/MeloTTS/blob/main/docs/install.md#python-api)
- `output_path=None`이면 음성 배열을 반환하고, 파일 저장 시 SoundFile을 사용한다. [MeloTTS API 소스](https://github.com/myshell-ai/MeloTTS/blob/main/melo/api.py)
- SoundFile은 MP3 쓰기 예제를 제공한다. 실제 설치 환경에서 쓰기·읽기 시험을 통과해야 채택한다. [SoundFile](https://github.com/bastibe/python-soundfile#controlling-bitrate-mode-and-compression-level)
- Ollama의 로컬 chat API는 JSON schema를 지정한 구조화 응답을 지원한다. [구조화 출력](https://docs.ollama.com/capabilities/structured-outputs)
- QMediaPlayer는 재생 위치와 상태를 제공한다. 대상 OS에서 MP3 디코딩과 오디오 출력을 별도로 시험한다. [Qt 공식 문서](https://doc.qt.io/qtforpython-6/PySide6/QtMultimedia/QMediaPlayer.html)

## 5. 데이터 계약

### 5.1 메모리 자료형

- `Settings`: 입력 언어 `ko`, 출력 언어 `en-US`, style_id, engine_id, voice_id, speed, storage_root, library_roots, translation_model.
- `VoiceInfo`: id, label, locale, gender(`male`/`female`/`unknown`), engine_id. 확인되지 않은 성별은 unknown.
- `ConversionRequest`: UUID request_id, 입력 원문, 설정 사본. 시작 후 변경 불가.
- `TranslationResult`: 순서가 있는 영어 문장 목록. 영어 전체 텍스트는 이 목록을 줄바꿈으로 연결해서 계산.
- `AudioBuffer`: 유한한 값의 1차원 PCM 배열, sample_rate > 0. 이 앱의 초기 출력은 mono.
- `SentenceAsset`: 0부터 시작하는 index, text, 상대 MP3 경로, 읽어서 확인한 duration_ms.
- `StudyArtifact`: artifact_id, 원문, 설정 사본, 문장 목록, 전체 MP3 경로, 생성 시각, 임시/저장 상태.

문장 번호는 내부에서 0부터, 화면과 파일 이름은 1부터 시작한다. 인덱스와 파일 이름을 변환하는 함수는 한 곳에만 둔다.

### 5.2 서비스 계약

```python
class Translator(Protocol):
    def translate(self, request: ConversionRequest) -> TranslationResult: ...

class SpeechSynthesizer(Protocol):
    def list_voices(self) -> list[VoiceInfo]: ...
    def synthesize(self, text: str, voice_id: str, speed: float) -> AudioBuffer: ...

class StudyRepository(Protocol):
    def save(self, artifact: StudyArtifact, root: Path) -> StudyArtifact: ...
    def list_entries(self, roots: list[Path]) -> list[LibraryEntry]: ...
    def load(self, folder: Path) -> StudyArtifact: ...
```

서비스는 실패 시 `TranslationError`, `SpeechError`, `AudioEncodingError`, `StorageError`, `InvalidStudyError` 등 단계별 예외를 전달한다. 내부 원인은 로그에 기록하되 원문 일기·전체 번역·응답 본문은 기본 로그에 남기지 않는다. 빈 문자열이나 빈 파일을 성공으로 반환하지 않는다.

### 5.3 저장 형식

폴더: `YYYY-MM-DD_HHMMSS_<전체 UUID hex>/`. 이름을 일기 원문에서 직접 만들지 않는다.

```text
<학습자료 루트>/<학습 폴더>/
+-- manifest.json
+-- original.txt
+-- translation.txt
+-- full.mp3
+-- sentences/
    +-- 001.mp3
    +-- 002.mp3
```

manifest의 최소 형식 예시(값은 설명용):

```json
{
  "schema_version": 1,
  "artifact_id": "9ac6ba30-8fb8-4c99-809f-3f3ddedb3ed1",
  "created_at": "2026-09-24T20:45:00+09:00",
  "title": "퇴근 후 산책",
  "source_language": "ko",
  "target_language": "en-US",
  "style_id": "middle_age_daily",
  "translation_model": "실제로 사용한 모델 ID",
  "speech": {"engine": "melotts", "voice_id": "EN-US", "gender": "unknown", "speed": 1.0},
  "original_path": "original.txt",
  "translation_path": "translation.txt",
  "full_audio_path": "full.mp3",
  "sentence_gap_ms": 1000,
  "sentences": [
    {"index": 0, "text": "I went for a walk.", "audio_path": "sentences/001.mp3", "duration_ms": 1800}
  ]
}
```

검증 규칙:

- UTF-8로 읽고 쓴다. created_at은 시간대가 있는 ISO 8601 문자열.
- schema_version 미지원이면 읽기를 중단하고 오류 안내. 무조건 최신 형식으로 덮어쓰지 않음.
- index는 0부터 빈틈없이 연속, text는 공백이 아닌 문자열, 경로는 중복 없음.
- 모든 파일 경로는 학습 폴더 내부의 상대 경로. 절대 경로, `..`, 외부로 연결되는 symlink는 거부.
- translation.txt는 manifest의 문장 목록을 `\n`으로 연결한 내용과 일치.
- `duration_ms`는 추정 숫자가 아니라 저장 후 디코딩한 프레임 수/샘플레이트로 계산.
- 제목은 원문 첫 비어 있지 않은 줄의 앞 30자로 생성. 제목 생성용 모델 요청은 하지 않음.

## 6. 화면과 상태 전환

ASCII 화면은 의도 문서를 따르되 다음을 최신 동작 기준으로 적용한다.

```text
[오늘의 학습] [학습 보관함] [환경설정]

오늘의 학습:
  [일기 입력창]
  [변환]
  [영어 번역창: 읽기 전용]
  현재 문장 / 전체 문장 수, 진행 및 오류 상태
  [재생 또는 일시정지] [정지]
  R: 반복 / Space: 다음 문장
  [저장]

학습 보관함:
  [검색어] [찾기]
  날짜 | 제목 | 문장 수 | 스타일
  목록 항목 한 번 클릭 -> 오늘의 학습 탭, 첫 문장 대기
  [저장 폴더 열기]

환경설정:
  미국식 영어, 회화 스타일, 지원되는 성별과 음성, 생성 속도
  저장 위치 [폴더 선택]
  [설정 저장] [취소]
```

MeloTTS를 선택했으면 “로컬 생성”을 표시한다. edge-tts를 실제 채택한 경우에만 온라인 생성 및 외부 전송 안내를 표시한다. 모델·Python 경로 같은 개발 설정은 일반 학습 화면에 노출하지 않는다.

상태는 하나의 큰 문자열 대신 다음 축으로 관리한다.

- 작업: `IDLE`, `CONVERTING`, `SAVING`, `LOADING`.
- 자료: `NONE`, `TEMP_READY`, `SAVED_READY`.
- 재생: `STOPPED`, `PLAYING`, `PAUSED`.
- 편집: `input_dirty`와 별도 원문 버퍼. 현재 자료의 원문을 직접 변경하지 않음.

| 상태 | 변환 | 재생/정지 | 저장 | 자료 전환 |
| --- | --- | --- | --- | --- |
| IDLE + NONE | 입력이 있으면 가능 | 불가 | 불가 | 가능 |
| IDLE + TEMP_READY | 가능 | 가능 | 가능 | 미저장 보호 후 가능 |
| IDLE + SAVED_READY | 가능 | 가능 | 불가 | 가능 |
| CONVERTING / SAVING / LOADING | 불가 | 불가 | 불가 | 불가 |

- 작업 시작 직전에 재생을 정지한다.
- 변환 중 입력창도 잠근다. 완료 후 편집을 허용하되 기존 결과와 다른 입력이면 “입력이 변경되었습니다. 다시 변환해 주세요.”를 표시한다.
- 결과가 있는 상태의 저장은 결과를 만들 때의 원문·설정을 저장한다. 화면에서 나중에 수정한 원문을 이전 MP3와 섞어 저장하지 않는다.
- 탭 이동만으로 자료를 버리지 않는다. 실제 목록 항목을 열거나 새 결과로 바꾸거나 종료할 때만 미저장 보호를 적용한다.
- 처음 입력한 일기로 변환할 때는 소실 경고를 띄우지 않는다. 변환 실패 시 입력 원문과 이전 정상 결과를 유지한다.

미저장 보호의 구체적 선택:

1. 미저장 변환 결과: `저장 후 계속 / 결과 버리고 계속 / 취소`. 저장 실패 시 예정된 이동·종료를 실행하지 않음.
2. 아직 변환하지 않은 편집 초안: `초안 보관 후 계속 / 초안 버리기 / 취소`. 초안 보관은 앱 데이터의 draft.json에 기록하며 MP3 보관함에는 넣지 않음.
3. 둘 다 있으면 순서대로 처리하고, 저장할 결과와 입력 초안이 다르다는 점을 안내한다.
4. 시작 시 남은 초안·임시 완성 결과가 있으면 복구를 제안한다. 사용자 결정 전 자동 삭제하지 않음.

## 7. 번역 구현 규칙

스타일 ID를 고정한다: `middle_age_daily`, `easy_daily`, `casual`, `polite_daily`, `work_daily`. 한국어 표시명은 의도 문서의 다섯 스타일과 대응한다.

로컬 Ollama에 `/api/chat` 요청을 보낸다. `stream=false`, 낮은 temperature, `format`에 문장 배열 schema를 전달한다. 연결/읽기 시간 제한을 설정하고 긴 초기 모델 로딩이 예상되면 진행 상태를 표시한다. 180초를 초기 요청 제한 제안값으로 두고 환경검증 결과로 조정한다.

응답 계약:

```json
{"sentences": ["First complete sentence.", "Second complete sentence."]}
```

프롬프트 지침:

- 사용자의 일기 내용은 번역 대상 데이터로 취급한다.
- 한국어의 사건·사람·시간·긍정/부정·감정을 보존한다.
- 미국식 영어와 선택 스타일로 번역한다.
- 새로운 사실, 해설, 발음 표기, 제목을 넣지 않는다.
- 각 배열 원소는 학습에서 한 번에 재생할 완결된 문장이다.
- JSON 이외의 내용을 반환하지 않는다.

검증 및 실패 처리:

- JSON 구조·문자열·빈 목록을 검사한다. 설명문을 임의로 잘라 성공 처리하지 않는다.
- 문장 구분은 응답 배열을 사용한다. `split('.')`로 약어와 소수를 잘라내지 않는다.
- 입력은 2~3줄을 권장하되 줄 수로 차단하지 않는다. 과도한 길이 방지를 위한 초기 최대 입력은 2,000자로 제안하고 화면에 안내한다. 무단 자르기 금지.
- 출력은 최대 30문장, 문장당 1,000자로 제한하여 비정상 응답을 감지한다. 한도 초과는 명확한 오류로 처리한다.
- 형식 오류에 한해 교정 요청 1회 후 중단한다. 무한 재시도 금지.
- 한국어→영어의 의미 보존과 스타일 품질은 schema 검증으로 보장되지 않으므로 수동 검수한다.

## 8. 음성 생성과 MP3 저장 규칙

1. TTS 작업자에서 영어 모델을 최초 필요 시 로딩하고 동일 작업자에서 재사용한다.
2. `model.hps.data.spk2id`에 실제 voice_id가 있는지 확인한다.
3. 문장별로 `tts_to_file(..., output_path=None, speed=...)`를 호출한다.
4. 반환 PCM이 비어 있지 않고 NaN/Inf가 없으며 샘플레이트가 유효한지 확인한다.
5. float mono PCM의 진폭이 허용 범위를 벗어나면 명시적인 정규화 정책을 적용하고 기록한다. 조용한 음성을 임의 증폭하지 않는다.
6. `soundfile.write(path, pcm, sample_rate, format='MP3')`로 문장 파일을 기록한다. 이어 읽기와 실제 재생 검증을 수행한다.
7. 같은 샘플레이트의 원본 PCM 사이에 정확히 1초의 0 배열을 넣고 합친다. 마지막 문장 뒤에 간격을 추가하지 않는다.
8. 합친 PCM을 한 번 인코딩하여 full.mp3를 만든다. MP3 바이트를 붙이거나 문장 MP3를 반복 인코딩하지 않는다.
9. 작업 중 PCM과 파일은 임시 결과에 둔다. 저장 버튼은 이를 영구 저장소에 확정하는 별도 단계다.

한 문장 내부에서 MeloTTS가 여러 조각으로 처리하더라도 앱의 문장 ID는 입력 배열 기준을 유지한다. sample_rate를 24,000 등으로 하드코딩하지 않는다. 모델에서 받은 값을 사용한다. 엔진을 섞어 샘플레이트가 다른 경우 초기 버전에서는 명확히 실패 처리하고, 리샘플링은 필요성이 생긴 뒤 별도 구현한다.

MP3 직접 쓰기가 실패하면 성공으로 보고하지 않는다. 환경 호환 버전 조합을 먼저 확인한다. WAV→별도 인코더 대안이 필요하면 의존성·설치 절차를 계획에 추가한 뒤 구현한다.

## 9. 영구 저장과 보관함 규칙

앱 설정·초안·임시 자료는 Qt QStandardPaths로 찾은 사용자 앱 데이터 경로에 둔다. 학습 자료 기본 위치는 사용자 문서 폴더 아래 `영어회화/학습자료`로 제안한다. 시작 시 문서 경로가 없거나 쓸 수 없으면 폴더 선택을 안내한다.

저장 알고리즘:

1. artifact_id는 변환 성공 결과에 한 번 부여하며 저장 재시도 때 바꾸지 않는다.
2. 재생을 중지하고 저장 버튼을 잠근다. 앱은 동일 사용자 데이터 경로에서 한 인스턴스만 실행하도록 잠금 파일을 사용한다.
3. 저장 대상 루트 안에 `.pending-<artifact_id>`를 만든다. 이 폴더는 보관함 검색에서 제외한다.
4. 원문·번역·음성 파일을 복사하고 manifest를 마지막에 쓴다. 원본 임시 자료는 아직 삭제하지 않는다.
5. 실제 파일을 읽어 계약을 검증한다. 파일 핸들을 모두 닫는다.
6. 같은 파일시스템 내에서 최종 고유 폴더 이름으로 rename하여 확정한다. 기존 최종 폴더가 있으면 동일 ID와 유효 내용을 확인해 저장 완료 여부를 판정하고 덮어쓰지 않는다.
7. 성공한 경우에만 화면을 SAVED_READY로 바꾸고 목록을 갱신한다.
8. 실패하면 원래 임시 결과를 유지하고 다시 저장 가능하게 한다. 삭제는 이번 작업이 만든 pending 폴더에만 한정한다.

폴더 rename은 부분 자료 노출을 줄이는 장치다. 전원 장애까지 무조건 안전하다고 표현하지 않는다. 시작 시 최종 폴더도 구조 검증하고 손상 항목은 별도 오류로 표시한다.

보관함은 초기 버전에서 DB 없이 manifest 목록으로 구성한다. 날짜 내림차순으로 정렬하고 날짜·제목·원문으로 검색한다. 한 자료가 손상되어도 정상 자료 목록은 표시한다. 오래된 저장 위치도 library_roots에 유지한다. 검색 대상 원문 읽기는 작업 스레드에서 수행한다.

목록 클릭 처리:

- 표의 실제 항목 클릭 신호만 연결한다. 목록 갱신에 따른 자동 선택 신호로 자료를 열지 않는다.
- 중복 클릭 중 LOADING이면 추가 요청을 무시한다.
- 정상 자료를 읽으면 오늘의 학습 탭에 적용하고 첫 문장에서 대기한다. 자동 재생하지 않는다.
- 불러오기가 실패하면 현재 학습 내용을 보존하고 오류를 표시한다.
- TTS·번역 서비스가 설치되지 않았더라도 저장 자료의 재생이 가능하도록 모델 import와 초기화를 분리한다.

## 10. 재생과 작업 스레드 규칙

재생 관리자는 현재 자료 ID, 문장 index, 선택된 파일, 재생 위치를 갖는다. QMediaPlayer와 QAudioOutput은 GUI 스레드에서 유지한다.

- 재생: STOPPED이면 해당 문장 0ms에서 시작, PAUSED이면 현재 위치에서 재개.
- 일시정지: 위치를 유지한다.
- 정지: stop 후 위치 0ms, 문장 index 유지.
- 자연 종료: STOPPED로 전환하고 index 유지. 전체 MP3로 소스를 바꾸지 않음.
- R: 현재 문장을 0ms부터 다시 시작.
- Space: 다음 문장이 있으면 이전 재생을 정지하고 다음 파일 재생. 마지막이면 상태 안내만 하고 재생 중 문장은 유지.
- 새 파일 로딩은 비동기일 수 있다. 파일·선택 ID를 확인한 뒤 재생하며, 이전 파일의 늦은 종료/오류 신호가 새 선택을 바꾸지 않게 한다.
- 연속 Space는 의도한 최종 선택만 재생하고 오래된 로딩 완료로 이전 문장이 다시 들리지 않게 한다.
- 재생 영역의 R/Space 이벤트를 직접 처리하고 처리한 이벤트는 소비한다. Space가 버튼 클릭과 다음 문장 이동을 동시에 발생시키지 않게 한다.
- 입력창·검색창·설정 입력·다른 탭에서는 학습 단축키 비활성화. 키 자동 반복은 무시한다.
- 실제 플레이어 오류는 오류 상태로 표시하고 재생 중이라는 표시를 제거한다.

번역·TTS·저장 작업자는 UI를 수정하지 않고 `progress(request_id, stage, current, total)`, `succeeded(request_id, result)`, `failed(request_id, error)` 신호를 보낸다. controller는 현재 request_id와 다른 결과를 무시한다. 모델을 여러 스레드에서 동시에 호출하지 않는다.

작업 중 닫기를 누르면 화면을 즉시 파괴하지 않는다. 중단 요청을 설정하고 작업 경계에서 정리 후 종료한다. HTTP에는 timeout을 적용하고 TTS 호출 도중 QThread를 강제 종료하지 않는다. 초기 버전은 실행 중 TTS 문장을 마칠 때까지 기다릴 수 있음을 안내한다.

## 11. 단계별 실행 계획

### 단계 0. 기존 환경 및 기술 위험 확인

수정/생성: `scripts/check_environment.py`, `docs/환경검증.md`.

- 기존 앱의 Python·패키지 버전과 사용 OS를 확인한다. 정보가 없으면 미확인으로 기록한다.
- 새 가상환경에서 MeloTTS 영어 모델, soundfile MP3 쓰기, Qt MP3 재생, 로컬 번역을 각각 작게 시험한다.
- 음성 목록과 남녀 선택 가능성을 실제로 확인한다.
- Python/패키지 버전 및 모델 준비 절차를 고정한다.

완료 기준: 검증한 플랫폼에서 영어 음성 → MP3 → 플레이어 청취가 성공. 성별 미지원은 별도 미해결로 기록. 실패해도 대체 서비스로 다음 UI/저장 단계 개발은 가능하나 실제 엔진 통합 완료로 처리하지 않는다.

### 단계 1. 프로젝트 골격과 데이터 계약

수정/생성: pyproject, domain, paths, 기본 실행 모듈, 계약 테스트.

- 위 디렉터리와 자료형을 만든다. 의존성은 주입 가능하게 한다.
- 테스트 임시 디렉터리만 사용하는 fixture를 만든다.
- 모델 없이 모듈 import와 빈 창 실행이 가능하게 한다.

완료 기준: 잘못된 manifest 경로·인덱스·빈 문장이 거부되고 정상 계약이 직렬화/복원된다.

### 단계 2. 저장소부터 구현

수정/생성: repository, config, 저장소 테스트.

- 테스트용 짧은 오디오 자료로 pending→확정 저장을 구현한다.
- 디스크 오류 주입, 중복 저장, 손상 자료 조회, 한글 경로, 초안 보관을 검증한다.
- 설정 파일도 임시 파일 작성 후 교체한다. 실패 시 기존 설정 유지.

완료 기준: 저장 실패가 이전 자료를 손상시키지 않고 재시도로 같은 자료가 한 번만 저장된다.

### 단계 3. 세 탭과 대체 서비스 연결

수정/생성: ui 전체, controller 초기 상태, test_ui.

- 정확히 지정된 버튼과 텍스트박스를 배치한다. 크기 조절 시 입력창이 확장되게 한다.
- 대체 번역·음성 결과는 테스트/개발 모드에만 제공한다. 일반 모드에서 가짜 번역을 실제 결과로 표시하지 않는다.
- 표 클릭 → 첫 탭 이동, 저장 버튼 상태, 미저장 보호를 구현한다.

완료 기준: R02/R03/R08/R09를 GUI 테스트로 확인하고 저장 전 보관함이 증가하지 않음.

### 단계 4. 실제 번역 연결

수정/생성: translator, prompts, smoke_translation, 계약 테스트.

- schema 기반 응답과 형식 오류 1회 교정을 구현한다.
- 서버 중단·timeout·잘못된 JSON·빈 응답을 오류로 처리한다.
- 다섯 스타일을 동일한 일기 집합으로 평가한다.

완료 기준: 의미·시제를 유지하는 번역을 사람이 검수하고 채택 모델을 기록. 네트워크 실패에도 UI가 반응함.

### 단계 5. MeloTTS 및 soundfile 연결

수정/생성: speech, audio_files, smoke_melotts, 오디오 테스트.

- 기존 코드가 제공되면 영어 모델 로딩·음성 저장 방식을 먼저 확인하여 재사용한다.
- 영어 PCM 생성, 문장 MP3 및 전체 MP3, 오디오 검증을 구현한다.
- 실제 음성이 준비되지 않으면 남녀 UI를 임의 활성화하지 않는다.

완료 기준: 적어도 미국 영어 한 음성의 문장/전체 MP3 생성·청취 성공. 남녀 요구 전체 통과는 별도 확인 필요.

### 단계 6. 비동기 변환·저장 연결

수정/생성: workers, controller, 상태 테스트.

- 원문·옵션 사본과 request_id를 작업에 전달한다.
- 변환 성공 시 TEMP_READY, 저장 성공 시 SAVED_READY로 구분한다.
- 연속 클릭, 저장 실패, 오래된 작업 응답, 종료 요청을 처리한다.

완료 기준: 긴 작업 중 창이 멈추지 않고 입력·음성·저장 파일이 다른 작업과 섞이지 않음.

### 단계 7. 문장 재생 및 단축키

수정/생성: playback, study_tab 이벤트 처리, 재생 테스트.

- 시작/일시정지/정지/종료/R/Space 전이를 구현한다.
- 마지막 문장, 빠른 연속 키, 입력창 Space와 R을 검증한다.

완료 기준: 실제 음성으로 한 문장씩 재생되고 일시정지 위치가 보존됨. 가짜 플레이어 테스트만으로 완료 처리하지 않음.

### 단계 8. 보관함·옵션·재시작 복구

수정/생성: library_tab, settings_tab, repository, config, 복구 테스트.

- 저장 경로 변경 후 기존 위치도 조회한다.
- 목록 갱신은 백그라운드에서 수행하고 날짜순·검색을 제공한다.
- 옵션 취소는 기존 설정 유지, 옵션 저장은 다음 변환부터 적용한다.
- 모델 서버를 종료하고 저장된 파일만으로 재학습한다.

완료 기준: 앱 재시작·오프라인 학습·초안 복구·손상 항목 처리 성공.

### 단계 9. 통합 검증과 전달

수정/생성: README, docs/수동검증.md, lock 파일, docs/구현진행.md.

- 아래 인수 시나리오를 실행하고 결과를 기록한다.
- 설치·모델 다운로드·실행·저장 경로·복구 방법을 README에 적는다.
- 대상 OS와 실행 환경이 확인된 뒤 배포 형태를 결정한다. 초기에는 재현 가능한 가상환경 실행을 전달하고, 실행 파일 패키징은 별도 검증한다.

완료 기준: 확인된 요구 ID별 증거가 있으며 미해결 항목이 명시됨. 남녀 음성 선택 등 필수 항목이 남았다면 전체 완료로 보고하지 않음.

## 13. 구현자가 매 단계 남길 보고 형식

```text
단계 번호와 이름:
변경 파일:
실행한 명령 및 결과:
사람이 확인한 동작:
통과한 요구사항/인수 테스트 ID:
남은 문제와 다음 단계:
```

초기 표준 검증 명령은 `python -m pytest`로 둔다. 실제 프로젝트 환경에 맞는 실행 명령은 골격을 만든 후 README에 확정한다. 자동 테스트에서 모델 다운로드·외부 서비스 호출을 기본으로 실행하지 않는다. 실제 모델과 오디오 장치 검증은 별도 통합/수동 절차로 기록한다.
